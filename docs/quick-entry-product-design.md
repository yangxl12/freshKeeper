# 保质期助手快速录入产品设计文档

> 版本：V0.1 · 状态：P0/P1 实施前产品稿 · 更新日期：2026-09-08 · 适用范围：最近物品快速复用、文字/语音一句话快录、专门拍日期

## 1. 文档定位

本文基于《freshKeeper-1 录入解决方案》的分析结论，并以当前仓库代码为事实基线，定义下一阶段 P0/P1 的产品范围、交互规则和验收标准。

输入方案文档中包含的历史对话、过程指令和外部方案仅作为分析材料，不直接构成本项目要求；本次实际建设范围以本文为准。

本文是 [MVP 产品设计文档 2](./mvp-product-design-v2.md) 的录入专项补充。发生冲突时：

- 新增物品的入口与录入流程以本文为准。
- 首页、库存、详情、历史、提醒和库存状态规则继续沿用现有产品文档。
- 代码现状与旧文档不一致时，以当前代码为基线。例如当前新增页默认数量为 `1`、单位为“件”，默认提醒天数来自用户设置，读取失败时使用 `1` 天。

本文不包含具体云服务选型、接口结构、数据库设计和模型提示词；这些内容应在产品方案确认后另行形成技术设计。

## 2. 背景与问题

当前新增入口会直接进入完整表单。页面同时展示基础信息、到期信息、分类与提醒三个区块，用户需要面对名称、数量、单位、分类、位置、日期和提醒等字段。

从现有保存规则看，系统最终仍需要一条完整、合法的库存记录：

- 名称必填，长度为 1～40 个字符。
- 数量为 1～9999 的整数，单位必填。
- 分类必填，存放位置选填。
- 到期信息必须是明确到期日，或“生产日期 + 保质期”。
- 提醒天数为 0～30 的整数。
- 最终写入必须继续通过现有服务端字段白名单和日期计算规则。

因此问题不是简单增加一个 AI 按钮，而是让用户用更少操作得到一条可核对的完整草稿，同时保证日期错误不会被直接写入库存。

### 2.1 当前代码能力映射

| 当前能力 | 代码位置 | 本期产品处理 |
| --- | --- | --- |
| 首页与库存新增入口 | `miniprogram/pages/home/index.ts`、`miniprogram/pages/inventory/index.ts` | 新增时改进快速录入；其他页面职责不变 |
| 完整新增、编辑与恢复表单 | `miniprogram/pages/item-form/` | 继续作为完整填写兜底，并保留编辑、恢复职责 |
| 库存保存输入 | `miniprogram/types/inventory.ts` 的 `InventorySaveInput` | 所有草稿最终映射到现有字段，不建设第二套库存对象 |
| 客户端保存服务 | `miniprogram/services/inventory-service.ts` 的 `saveItem` | 继续作为最终保存入口 |
| 服务端保存与校验 | `cloudfunctions/inventoryApi/index.js`、`validation.js` | 继续负责用户隔离、字段白名单、合法值和最终写入 |
| 日期计算 | `miniprogram/utils/date-key.ts` 与云函数日期模块 | “生产日期 + 保质期”继续使用现有日历计算口径 |
| 默认提醒天数 | `miniprogram/services/settings-service.ts`、当前新增页默认状态 | 优先使用用户设置，失败时保持现有 1 天兜底 |
| 埋点封装 | `miniprogram/utils/analytics.ts` | 新事件继续使用现有封装，但不上传业务原文 |
| 现有批量操作 | `miniprogram/pages/batch-operation/` | 仅处理库存，不扩展为批量新增 |

当前代码没有最近模板、临时草稿、语音转写、图片上传或 OCR 能力。本文中的相关流程都是待建设产品能力，不能在开发或验收时当作已有能力。项目当前配置的基础库版本为 `3.8.10`；技术设计必须基于所选语音/OCR 方案重新核对兼容性，不能默认客户端可直接调用任意识别服务。

## 3. 产品目标

### 3.1 核心目标

将新增物品从“逐项填写表单”改为“快速产生草稿、重点确认名称和日期、再加入库存”。

统一流程为：

```text
最近物品 / 文字 / 语音 / 日期照片
                ↓
          生成临时草稿
                ↓
        核对名称和到期信息
                ↓
       通过现有保存链路入库
```

北极星指标为：**每分钟正确保存的物品数**。识别调用次数、模型命中率等技术数据不是最终产品目标。

### 3.2 用户价值

- 重复购买的物品只补本批次日期，不再重复填写固定信息。
- 用户可以像说话一样描述物品，由系统拆成结构化草稿。
- 用户可以只拍包装上的日期区域，避免手动辨认和输入小字喷码。
- 识别不确定时明确让用户处理，不用“看起来完整”的错误结果换取表面速度。

### 3.3 体验目标

- 最近物品复用后，目标是在 10 秒内完成一条正确录入。
- 信息完整的一句话或清晰日期照片，目标是在 15 秒内完成一条正确录入。
- 任何识别方式失败后，用户已经输入、说出或选择的内容不能无提示丢失。
- 用户始终能够退回纯手动录入，不以麦克风、相机或智能服务可用为前提。

## 4. 范围与优先级

### 4.1 P0：最近物品快速复用

P0 同时建立统一的快速录入页和临时草稿确认方式，为 P1 的文字、语音和照片入口复用。

交付内容：

- 首页、库存页和空状态中的“新增物品”进入快速录入页。
- 展示用户最近录入的去重物品。
- 点击最近物品后复用非日期字段，清空旧批次日期。
- 在同一页补充新日期、核对草稿并保存；P1 上线后，同一日期区域再增加拍摄入口。
- 保留“完整填写”入口，进入现有新增表单。

### 4.2 P1：一句话快录与专门拍日期

P1 在统一草稿上增加三种输入能力：

1. 文字一句话解析。
2. 语音转文字后复用同一解析流程。
3. 只针对包装日期区域的拍照识别。

建议按以下顺序交付，前一步稳定后再开放下一步：

```text
P1-A 文字一句话 → P1-B 语音一句话 → P1-C 拍日期
```

### 4.3 本次不做

- 包装正面商品识别和通用“拍物品自动入库”。
- 条码、商品库、药品追溯码。
- 任意多图批量上传、连续拍摄队列和小票识别。
- 常用物品置顶、手工模板管理和模板跨用户共享。
- 根据商品类别、经验保质期或模型常识猜测日期。
- 开封日期及“开封后 12M”等独立保质期模型。
- 自动保存、后台静默保存或识别成功后跳过确认。
- 对现有编辑、重新入库、详情和批量处理流程进行重构。
- “保存并继续”与连续录入模式；待单条快录数据验证后再评估。

## 5. 整体产品结构

### 5.1 入口调整

当前首页和库存页的新增按钮都直接进入完整表单。改造后：

| 入口 | 新行为 |
| --- | --- |
| 首页“新增物品” | 进入快速录入页；P0 独立发布且该用户没有最近物品时，直接进入现有完整表单 |
| 库存页“新增物品” | 进入快速录入页；P0 独立发布且该用户没有最近物品时，直接进入现有完整表单 |
| 空库存“新增物品” | 进入快速录入页；P0 独立发布且该用户没有最近物品时，直接进入现有完整表单 |
| 物品详情“编辑” | 保持进入现有完整表单 |
| 回收站“重新编辑并入库” | 保持进入现有完整表单 |

快速录入只负责新增。编辑和恢复需要显示已有记录、版本冲突及状态规则，不与智能草稿混用。

### 5.2 快速录入首页

```text
快速录入

┌────────────────────────────┐
│ 牛奶2盒，9月12日到期，放冰箱  [话筒] │
└────────────────────────────┘
[生成草稿]                         [拍日期]

最近使用
鲜牛奶  2盒 · 冰箱                 >
酸奶    4杯 · 冷藏                 >
布洛芬  1盒 · 药箱                 >

完整填写
```

上图是 P1 全部能力开放后的页面。P0 单独运行时只展示最近物品、日期补充和完整填写；尚未开放的文字、语音、拍日期入口不显示为不可用占位。

交互原则：

- 一句话输入框是主入口，语音是同一输入框的另一种输入方式。
- “拍日期”是与输入框并列的辅助入口，不先展示录入方式选择弹窗。
- 最近物品有数据才显示；无历史时整段隐藏，不展示无意义空状态。
- “完整填写”始终可见，但视觉层级低于快速录入主操作。
- 页面只有一个当前草稿区；产生多条草稿时按顺序展示，避免多个弹窗来回切换。

### 5.3 草稿确认区

草稿不是库存记录。在用户点击确认保存前，不得进入 `inventory_items`，不得创建提醒任务，也不得影响首页和库存统计。

草稿区优先展示：

1. 物品名称。
2. 到期信息。
3. 数量与单位。
4. 分类、位置和提醒摘要。

名称和到期信息始终展开。其他信息默认使用一行摘要，用户点击“更多信息”后可以修改全部字段。主按钮文案为“确认加入库存”；多条草稿时为“加入库存（N）”，其中 `N` 只统计当前已选择且可保存的草稿。待补充草稿不能被选中，但不阻塞其他完整草稿保存；没有任何可保存草稿时，主按钮不可用。

多条草稿默认选中所有“可保存”项；用户可以取消某项或删除某项后再提交。待补充、待确认和保存失败项不计入 `N`，也不会因其他项成功保存而被清除。

草稿状态分为：

| 状态 | 展示与操作 |
| --- | --- |
| 识别中 | 保留原输入，显示进行中状态，可取消本次识别 |
| 待补充 | 明确标出缺失字段；该草稿不可保存，多条场景下不阻塞其他完整草稿 |
| 待确认 | 标出有歧义字段，用户完成选择或修改后才可保存 |
| 可保存 | 必填字段完整，展示最终将保存的值 |
| 保存中 | 禁止重复提交 |
| 部分失败 | 多条草稿中保留已失败项及原因，不重复保存已成功项 |

用户离开存在未保存草稿的页面时，应提示“放弃本次录入？”；P0/P1 不要求在杀掉微信进程后恢复草稿。

## 6. P0：最近物品快速复用

### 6.1 最近物品口径

“最近使用”从当前用户已经成功保存的库存记录中产生，不新增“模板管理”概念。

- 数据范围包含使用中和已用完记录。
- 已删除、回收站和旧版已丢弃记录不参与推荐。
- 按最近保存或更新的记录排序。
- 按标准化后的完整名称去重，同名时只保留最近一条的配置。标准化只做 Unicode NFKC、去除首尾空白、连续空白折叠为一个空格，以及拉丁字母大小写统一；规格数字、标点和有意义的内部空格保留，不做模糊相似合并。
- 首屏最多展示 6 项；P0 不提供查看更多、置顶或删除最近记录的管理入口。
- 如果用户没有符合条件的记录，则隐藏“最近使用”。

去重验收示例：` 鲜牛奶 ` 与 `鲜牛奶` 视为同名；`C-100` 与 `c-100` 视为同名；`牛奶 250ml` 与 `牛奶250ml` 因内部空格不同而视为不同名称。这样可以消除明显输入差异，又不把不同规格静默合并。

### 6.2 复用字段

点击最近物品后，复制以下信息：

| 字段 | 复用规则 |
| --- | --- |
| 名称 | 复制 |
| 数量 | 复制，可在草稿中修改 |
| 单位 | 复制 |
| 分类 | 复制 |
| 存放位置 | 复制 |
| 提醒天数 | 复制 |
| 到期录入方式 | 上次为“按保质期计算”时保留该方式，否则使用直接到期日 |
| 保质期数值与单位 | 仅上次为“按保质期计算”时复制 |
| 生产日期 | 永远清空 |
| 到期日期 | 永远清空 |
| 库存状态、版本、记录编号 | 永远不复制 |

**旧日期不得以默认值、占位值或折叠字段的形式进入新草稿。** 最近物品的核心是复用物品资料，不是复制上一批库存。

### 6.3 操作流程

```text
点击最近物品
  ↓
生成已填好固定信息的草稿
  ↓
日期区域自动获得焦点
  ├─ 选择到期日
  ├─ 填生产日期并沿用保质期
  └─ 拍日期（P1 上线后）
  ↓
确认加入库存
```

若最近记录使用“生产日期 + 保质期”，草稿保留保质期数值和单位，用户只需补新的生产日期；最终到期日仍由现有日期规则计算。

### 6.4 异常与边界

- 最近列表加载失败不阻塞当前已开放的其他录入方式和完整填写入口。
- P0 若独立上线且当前用户没有最近物品，应直接进入现有完整表单，不能增加一张只有“完整填写”按钮的空中间页；P1 任一快录方式开放后再统一进入快速录入页。
- 原记录的字段不再符合当前校验规则时，不直接生成可保存草稿；无效字段回退到当前默认值并标记待确认。
- 同名物品存在不同规格时，P0 取最近记录，不尝试自动合并或展示多个同名模板。
- 选择最近物品后允许修改名称；修改不会回写旧记录。

## 7. P1-A/P1-B：文字与语音一句话快录

### 7.1 统一输入模型

文字和语音必须进入同一条产品链路：

```text
手动输入文字 ─────────────┐
                          ├─ 可编辑原文 → 结构化解析 → 草稿
按住说话 → 转写为文字 ────┘
```

语音能力只负责获得文字，不单独定义库存字段、日期规则或保存逻辑。语音转写完成后，转写文本回填到输入框并自动生成草稿；用户可修改文本后“重新生成”。

### 7.2 支持提取的字段

P1 支持从一句话提取：

- 物品名称。
- 数量与单位。
- 分类。
- 存放位置。
- 明确的到期日。
- 明确的生产日期与保质期。

提醒天数不从自然语言中提取。新物品使用用户当前默认提醒天数；读取失败时沿用现有 `1` 天默认值。这样避免“提醒我三天后”和“提前三天提醒”等表达干扰到期日期。

字段补全优先级：

| 字段 | 优先级 |
| --- | --- |
| 名称、数量、单位、分类、位置 | 用户明确表达 > 最近同名物品资料 > 当前新增默认值 |
| 到期信息 | 用户明确表达 > 用户在草稿中选择或拍摄；禁止从最近记录或商品常识补全 |
| 提醒天数 | 最近同名物品设置 > 用户默认设置 > 现有兜底值 1 天 |

### 7.3 日期解释规则

日期是高风险字段，遵循以下规则：

- 完整年月日可直接转为候选日期，并在草稿中展示完整结果。
- 明确相对日期，如“明天到期”“还有 3 天到期”，可按本次解析使用的上海自然日换算，并展示换算后的完整日期。
- 到期日只有月日、没有年份时，解释为从今天起最近一次不早于今天的该月日；草稿必须明确展示补全后的年份。
- 只有年份和月份、没有具体日期时，保持日期未完成，不能默认当月 1 日或最后一天。
- 只有“保质期 7 天”但没有生产日期时，保持生产日期未完成，不能默认今天生产。
- “生产日期 + 保质期”由现有日历规则计算到期日，不让识别模型直接计算。
- 同一句中出现多个日期但缺少明确含义时，列出候选项让用户指定“生产日期”或“到期日期”。
- 无法判断是日期、批号还是规格数字时，不写入日期字段。
- 识别出的到期日早于今天时允许保存，但必须显示“该物品已过期”的明确提示，与现有库存能力一致。

### 7.4 单条与多条

一句话允许使用分号、停顿或连接词描述多件物品，P1 单次最多生成 5 条草稿。超过 5 条时不截断保存，应提示用户分次录入。

示例：

| 原始输入 | 预期结果 |
| --- | --- |
| “鲜牛奶 2 盒，2026 年 9 月 12 日到期，放冰箱” | 1 条可保存草稿；直接到期日为 `2026-09-12` |
| “布洛芬 1 盒，生产日期 2026 年 9 月 1 日，保质期 2 年，放药箱” | 1 条草稿；按现有规则计算到期日 |
| “牛奶 2 盒 9 月 12 日到期；酸奶 4 杯 9 月 15 日到期” | 2 条草稿，分别核对和保存 |
| “酸奶明年 3 月到期” | 名称可填，日期待补充，不得猜测具体日 |
| “这盒牛奶能放 7 天” | “能放 7 天”不等于包装保质期，日期保持为空 |

多条草稿允许：

- 单独修改或删除某一条。
- 一次保存全部已完整草稿。
- 某条校验或保存失败时，不影响其他合法草稿；失败项保留原值和错误原因。
- 已保存成功的草稿不得因重试失败项而重复入库。

### 7.5 语音交互

- 采用“按住说话、松开识别”的短句交互，最长 30 秒。
- 开始录音后显示录音状态、时长和取消提示。
- 手指移出有效区域并松开时取消，不提交该段录音。
- 首次使用前请求麦克风授权，并用当前动作说明用途。
- 用户拒绝或系统禁止授权时，保留文字输入和完整填写路径，并提供前往设置的入口。
- 无有效语音、环境噪声过大、转写超时或网络失败时，不生成虚假草稿；给出重试和改用文字入口。
- 原始音频仅用于本次转写，不出现在库存详情或历史中。

### 7.6 解析失败处理

- 完全无法解析：保留原文，提示“没有识别出物品和日期”，提供重新生成或完整填写。原文继续保留在当前快速录入页的临时状态中；进入完整表单时不把整段原文自动当作名称，用户返回快速录入页后仍可重试或手动改写。
- 只识别出名称：生成待补充草稿，直接突出日期入口。
- 只识别出日期：生成待补充草稿，名称获得焦点；不把 OCR/语音中的其他文本强行当名称。
- 智能服务不可用：保留原文；若已有部分字段被可靠识别，只把这些字段带入完整表单，否则打开现有表单默认值。不得把未解析的原文静默写入名称，也不能要求用户重新输入后才允许重试。
- 输入包含敏感或无关内容：只保留本次草稿需要的字段，不将整段原文写入库存记录。

## 8. P1-C：专门拍日期

### 8.1 功能定位

功能名称统一为“拍日期”，不使用“拍物品识别”或“AI 识物”。该能力只解决包装日期难找、难读、难输入的问题，不承诺从商品正面照片识别物品名称。

入口位于：

- 快速录入页主操作区。
- 草稿的到期信息区域。
- 点击最近物品后的日期补充区域。

### 8.2 拍摄流程

```text
点击“拍日期”
  ↓
相机取景：提示将日期喷码放入框内
  ↓
拍摄并预览，可重拍
  ↓
识别日期文字和候选含义
  ├─ 唯一且明确 → 填入草稿，等待用户确认
  ├─ 多个候选   → 用户选择日期及含义
  ├─ 信息不完整 → 保留已识别部分，补充缺失字段
  └─ 无法识别   → 重拍或手动选择
```

P1 每次处理一张日期照片。相册选择可作为权限或现场拍摄不便时的辅助入口，但不支持一次选择多张。

### 8.3 识别结果规则

| 照片内容 | 产品行为 |
| --- | --- |
| 明确“有效期至/EXP/到期日”且只有一个完整日期 | 填入直接到期日，展示完整日期和识别文字 |
| 明确“生产日期/MFG”与“保质期” | 填入生产日期和保质期，由现有规则计算到期日 |
| 同时出现生产日期和到期日期 | 两者都展示，默认以明确标注的到期日作为最终值，用户仍可修改 |
| 明确到期日与“生产日期 + 保质期”计算结果不一致 | 标记“日期有冲突”，同时展示两个结果，必须由用户选择或修改后才能保存 |
| 到期日期早于生产日期 | 标记日期无效并阻塞保存，要求重新拍摄或手动修正 |
| 多个完整日期但含义不清 | 展示候选列表，由用户选择每个日期的含义 |
| 只有一个无标签日期 | 让用户选择“这是到期日”或“这是生产日期” |
| 只有月份、批号或无法组成合法自然日 | 不补造日期，提示重拍或手动填写 |
| “开封后 12M”等开封周期 | 明确提示当前版本暂不支持，不转换为到期日 |

识别结果旁应保留本次照片的日期区域缩略图或识别原文，帮助用户核对依据。用户保存或放弃本次草稿后，不再在产品中提供原图查看入口。

### 8.4 拍摄指导与失败反馈

- 取景框只引导对准日期区域，不要求把完整包装放入画面。
- 提示避开反光、阴影和弯曲边缘，并让喷码尽量占满取景框。
- 模糊或过暗时优先建议重拍，不输出一个高确定性的日期。
- 识别超时、网络失败时保留照片预览，允许重试本次识别或改为手动选择日期。
- 相机权限被拒绝时说明该权限只用于本次拍摄，并保留相册和手动选择路径。
- 拍摄日期不会自动创建物品；若名称为空，识别完成后必须继续补名称。

## 9. 统一草稿字段规则

| 字段 | 默认或来源 | 是否阻塞保存 | 确认要求 |
| --- | --- | --- | --- |
| 名称 | 最近物品、文字/语音提取或用户输入 | 是 | 始终展开显示 |
| 数量 | 最近物品、文字/语音提取，否则 `1` | 是 | 可在更多信息中修改 |
| 单位 | 最近物品、文字/语音提取，否则“件” | 是 | 可在更多信息中修改 |
| 分类 | 最近物品、明确提取，否则沿用当前新增默认“食品” | 是 | 摘要中可见 |
| 存放位置 | 最近物品、明确提取，否则为空 | 否 | 摘要中可见 |
| 到期录入方式 | 输入语义或最近物品的保质期方式，否则直接到期日 | 是 | 始终展开显示 |
| 生产日期 | 用户输入或明确识别 | 视模式而定 | 日期不完整时必须补充 |
| 保质期 | 最近物品或明确识别 | 视模式而定 | 与生产日期组合后计算 |
| 到期日期 | 用户输入、明确解析、OCR 候选或现有日期计算 | 是 | 始终显示完整年月日 |
| 提醒天数 | 最近物品、用户设置，否则 `1` | 是 | 摘要中可见 |

任何来源都不能绕过当前字段长度、数值范围、合法日期和服务端白名单。模型输出仅是草稿候选，不是可信库存数据。

## 10. 保存与反馈

### 10.1 保存规则

- 用户必须点击“确认加入库存”后才发起保存。
- 每条草稿最终转换为当前 `InventorySaveInput` 对应字段，继续调用现有保存能力。
- 服务端返回成功后，该条草稿才显示“已加入库存”。
- 多条草稿逐条展示保存结果；部分成功时不可把整个操作描述为失败。
- 网络失败允许原地重试，且必须避免重复点击造成重复记录。
- 保存成功返回来源页后，首页和库存页继续按现有 `onShow` 机制刷新。

### 10.2 手动兜底

用户从快速录入进入“完整填写”时：

- 如果尚无草稿，打开当前新增表单及其默认值。
- 如果已有草稿，将已识别的合法字段带入完整表单。
- 不确定日期不能在带入时变成确定日期。
- 完整表单仍使用现有校验、保存和错误反馈。

## 11. 状态、错误与权限

| 场景 | 必须提供的反馈 |
| --- | --- |
| 最近物品加载失败 | 该区域提示可重试，其他录入方式可继续使用 |
| 文字解析超时 | 保留原文，支持重试或完整填写 |
| 语音权限拒绝 | 说明如何开启，并保留文字输入 |
| 语音转写失败 | 保留页面状态，支持重录或文字修改 |
| 相机权限拒绝 | 保留相册与手动日期入口 |
| OCR 无日期 | 明确提示未找到日期，不自动填值 |
| 多日期冲突 | 列出候选及识别原文，要求用户选择 |
| 草稿字段不完整 | 精确定位字段，保存按钮不可用 |
| 保存校验失败 | 使用现有服务端错误，定位到对应草稿和字段 |
| 多条中部分保存失败 | 展示成功数、失败数和逐条原因，只重试失败项 |

## 12. 隐私与数据边界

- 麦克风、相机和相册均在用户主动操作时申请权限，不在打开页面时预授权。
- 权限文案必须说明数据用途是“识别本次录入内容或日期”。
- 音频、照片、语音原文和 OCR 原文默认不写入库存记录。
- 若识别必须临时上传媒体，处理完成后应按技术方案约定及时删除；不得作为商品图库或训练素材长期保留。
- 埋点不得包含物品名称、用户原始输入、语音文本、OCR 原文、图片、音频、OPENID 或其他可还原用户家庭库存的信息。
- 上线语音、相机或相册能力前，必须同步更新小程序隐私保护指引、权限声明和审核材料。

## 13. 数据指标

### 13.1 核心指标

- 从进入快速录入页到成功保存的中位时长，按最近、文字、语音、拍日期、完整填写分别统计。
- 每次快速录入会话成功保存的物品数。
- 草稿生成后成功保存率。
- 到期日期在保存前被用户修改的比例。
- 保存后 24 小时内再次编辑到期信息的比例，作为日期正确性的风险信号。

### 13.2 分能力指标

| 能力 | 关注指标 |
| --- | --- |
| 最近物品 | 展示率、点击率、点击后保存率、从点击到保存时长 |
| 文字一句话 | 可生成草稿率、字段补充率、放弃率、多条拆分成功率 |
| 语音一句话 | 授权率、有效转写率、转写后修改率、转写后保存率 |
| 拍日期 | 找到日期率、重拍率、多候选率、日期修改率、保存率 |
| 手动兜底 | 从智能入口转入完整填写的比例及最终保存率 |

建议增加不含业务原文的事件：

- `quick_entry_open`
- `recent_item_select`
- `quick_parse_result`
- `voice_permission_result`
- `voice_transcribe_result`
- `date_photo_result`
- `draft_field_corrected`
- `quick_entry_save_result`

事件只记录入口、结果枚举、耗时、草稿数量和字段名等非敏感信息。

## 14. 验收标准

### 14.1 P0 验收

- 首页、库存页和空库存新增入口进入快速录入页；详情编辑和回收站恢复仍走原流程。
- 最近物品只包含当前用户使用中或已用完的数据，按名称去重，最多展示 6 项。
- 点击最近物品可正确复用名称、数量、单位、分类、位置和提醒设置。
- 直接到期模式永不复制旧到期日；保质期模式只复用保质期，不复制生产日期和旧到期日。
- 未补齐新日期时不能保存。
- 完整填写入口始终可用，已有合法草稿字段可带入。
- 保存仍经过现有客户端和服务端校验，成功后首页与库存能刷新显示。

### 14.2 文字快录验收

- 可将包含名称、数量、单位、位置和明确到期日的单条文本生成正确草稿。
- 可解析“生产日期 + 保质期”，到期日由现有规则计算。
- 可将不超过 5 件、边界清晰的输入拆成多条独立草稿。
- 缺少具体日、缺少生产日期或存在日期歧义时不能猜值或保存。
- 原文可编辑并重新生成；解析失败和网络失败时原文不丢失。
- 多条草稿部分保存失败后，只重试失败项，不产生重复记录。

### 14.3 语音快录验收

- 首次主动录音时才申请麦克风权限。
- 正常录音可转写为可编辑文字，并与同样的手输文字得到一致草稿。
- 取消录音、无有效语音、权限拒绝、转写超时和网络失败都有明确可恢复路径。
- 语音识别不得绕过日期歧义和草稿确认规则。

### 14.4 拍日期验收

- 相机默认引导拍日期区域，并可重拍。
- 唯一明确的到期日期、生产日期加保质期、多日期、无标签日期、无日期五类结果均按本文规则处理。
- 多日期或无标签日期必须由用户指定含义；不完整日期不得补造具体日。
- 识别出的日期始终以完整年月日展示，并允许修改。
- 相机拒绝、OCR 超时、图片模糊和无日期时可改用相册或手动输入。
- 只有日期、没有名称时不能保存；拍照识别绝不自动入库。

### 14.5 回归验收

- 现有手动新增、编辑、重新入库、两种日期录入、提醒默认值及错误提示保持可用。
- 现有首页概览、库存筛选、详情处理、历史和回收站行为不变。
- 两个微信账号的最近物品和草稿结果相互隔离。
- 拒绝麦克风、相机、相册权限后，纯手动核心闭环仍可完成。
- 微信开发者工具完成主流程和异常状态验证，并在真机覆盖录音、拍摄、权限、安全区和弱网场景。

## 15. 发布顺序与停止条件

### 15.1 发布顺序

1. 建立快速录入页、统一草稿和完整填写兜底。
2. 上线最近物品复用，采集手动录入时长基线。
3. 上线文字一句话，先验证单条，再开放多条。
4. 语音转写接入同一文字解析器。
5. 上线日期拍摄，先覆盖明确到期日，再开放生产日期加保质期和多候选处理。

### 15.2 停止或降级条件

出现以下任一情况时，相应智能入口应降级为手动确认，不继续扩大范围：

- 日期结果无法说明来自哪段输入或哪个照片候选。
- 存在识别结果未经用户确认直接保存的路径。
- 重试可能重复创建库存记录。
- 媒体或原始识别文本的保存范围无法明确说明和清理。
- 语音或拍照权限拒绝后无法完成手动新增。
- 日期修改率或保存后短期改期率持续异常，但无法定位具体输入类型。

## 16. 后续但不属于本期

完成本期并获得真实数据后，再评估：

- 常用物品置顶和个人模板管理。
- 保存并继续、连续语音和连续拍摄。
- 包装正面名称识别与日期补拍组合。
- 个人条码与物品资料映射。
- 可恢复的跨会话批量草稿。
- 小票、订单截图和历史数据导入。
