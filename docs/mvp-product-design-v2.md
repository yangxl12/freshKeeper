# 保质期助手 MVP 产品设计文档 2

> 版本：V0.2 · 状态：页面结构调整方向稿 · 更新日期：2026-09-07
>
> 本文基于 [MVP 产品设计文档 V0.1](./mvp-product-design.md)，重点说明新增首页和库存页重构；未提及的录入、详情、提醒、历史与设置规则继续沿用原方案。

## 1. 调整目标

当前“首页”同时承载库存概览、搜索筛选和完整列表，用户查看全局状态与查找具体物品时容易互相干扰。

本次将两个任务拆开：

- **首页**：快速回答“现在有没有需要关注的物品、最该先处理什么、整体库存是否正常”。
- **库存**：集中展示和管理全部有效物品，让搜索与筛选可以直接点击、自由组合。

整体继续保持轻量，不增加复杂图表、报表或智能建议。

## 2. 信息架构

底部 Tab 调整为三项：

| Tab | 核心职责 |
| --- | --- |
| 首页 | 全局状态、优先处理物品、快捷入口 |
| 库存 | 全部有效物品、搜索与组合筛选 |
| 我的 | 默认设置、提醒说明、历史记录 |

小程序默认进入首页。新增/编辑页和物品详情页继续作为二级页面，不进入 Tab。

## 3. 首页

### 3.1 页面重点

首页只保留用户最关心的信息，第一屏优先展示：

1. **待处理总数**：已过期、今天到期和未来 7 天内临期物品的数量之和。
2. **状态概览**：过期、今天、临期、有效库存总数。
3. **优先处理**：最多展示 5 件最紧急物品，按已过期、今天到期、即将到期的顺序排列。
4. **快捷操作**：新增物品、查看全部库存。

首页不再放搜索框和完整库存列表，避免信息过载。

### 3.2 状态与跳转

- 点击状态概览，进入库存页并自动带入对应状态筛选；点击有效库存总数进入全部库存。
- 点击优先处理物品进入详情页，完成“查看 → 用完/丢弃”的处理。
- 待处理为 0 时，明确展示“近期状态良好”，不保留空白的紧急列表。
- 没有任何库存时，首页以“新增第一件物品”为唯一主操作。

### 3.3 页面结构示意

```text
今日状态
┌──────────────────────────┐
│ 待处理 4 件               │
│ 过期 1    今天 1    临期 2 │
│ 当前共 26 件库存          │
└──────────────────────────┘

优先处理
酸奶                已过期 1 天
感冒药                  今天到期
面包                    还有 2 天
                    查看全部库存

                         ＋ 新增
```

## 4. 库存页重构

### 4.1 页面结构

库存页从上到下固定为：

1. 搜索框
2. 种类筛选行
3. 状态筛选行
4. 清除条件入口（有筛选时出现）
5. 库存列表

原首页的全局概览移到新首页，库存页专注查找和管理。

### 4.2 搜索

- 搜索框位于页面最顶部，按物品名称搜索。
- 输入后自动刷新结果，不要求点击确认按钮。
- 有内容时提供一键清空；清空后保留已选的种类和状态。

### 4.3 两行直接筛选

所有选项直接平铺展示，不使用下拉框、弹窗或二次选择。

**第一行 · 种类**

`全部 / 食品 / 药品 / 日化 / 其他`

**第二行 · 到期状态**

`全部 / 过期 / 今天 / 临期 / 正常`

状态口径：

| 选项 | 条件 |
| --- | --- |
| 过期 | 到期日早于今天 |
| 今天 | 到期日等于今天 |
| 临期 | 距离到期 1～7 天 |
| 正常 | 距离到期超过 7 天 |

每一行均为单选，默认选中“全部”。选中态需要同时使用底色、描边和文字表达，不能只依赖颜色。两行选项在常见手机宽度内都应完整显示，不折叠为下拉选择。

存放位置继续展示在物品信息中，但不再占用主筛选区；后续只有在真实使用反馈表明它是高频条件时再考虑恢复。

### 4.4 组合规则

搜索、种类和状态按“同时满足”组合：

`名称包含搜索词 AND 属于所选种类 AND 符合所选状态`

- 种类与状态切换后立即生效，不需要“确定”。
- 点击某一行的“全部”，只清除该行条件，不影响其他条件。
- 有任意条件生效时显示“清除全部”，可一次恢复完整库存。
- 无匹配结果时保留当前条件，并提供“清除筛选”操作。

### 4.5 列表规则

- 只展示“使用中”的有效库存，已用完和已丢弃仍进入“我的 → 历史记录”。
- 结果统一按到期时间从近到远排列。
- 选择“全部状态”时可继续按到期状态分组；选中具体状态后直接展示该状态结果，减少重复标题。
- 新增按钮继续固定在易触达位置，并避免遮挡最后一条库存。

## 5. 关键交互闭环

```text
首页查看全局状态
  ├─ 点击状态 → 带筛选进入库存 → 查看物品详情
  ├─ 点击优先物品 → 查看详情 → 用完或丢弃
  └─ 点击新增 → 录入物品 → 返回后刷新首页与库存

库存查找物品
  └─ 搜索 + 种类 + 状态 → 组合结果 → 查看或处理物品
```

首页和库存共用同一套实时到期规则。新增、编辑或处理物品后，两个页面再次显示时都应刷新数据，避免概览与列表不一致。

## 6. 数据与实现边界

- 不新增库存业务字段；到期状态继续根据到期日实时计算，不写死在数据中。
- 首页概览和库存状态筛选可复用现有库存查询能力，按需补充统计项和状态参数。
- 搜索与筛选必须在服务端组合后再分页，不能只过滤当前已加载的一页。
- 首页只展示摘要和少量紧急物品，不为了“看起来丰富”增加趋势图、分类占比或消费建议。

## 7. 验收要点

- 底部清晰展示“首页 / 库存 / 我的”，默认进入首页。
- 首页数字与有效库存实时一致，5 件以内即可看到最紧急物品。
- 库存页顶部依次为搜索、种类、状态，所有筛选均可直接点击。
- 搜索、种类、状态任意两项或三项组合时结果正确。
- 从首页状态进入库存时，筛选条件和结果对应正确。
- 空库存、无待处理物品、无筛选结果和网络失败均有明确反馈。
- 小屏下筛选不重叠、不截断，触控区域足够，状态不只依赖颜色表达。

## 8. 本次不调整

- 新增/编辑、物品详情、提醒、历史记录和默认设置的核心流程。
- 分类、存放位置和库存业务状态的数据定义。
- 家庭共享、图表分析、AI 建议、购物清单等后续能力。
