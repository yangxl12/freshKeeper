# 保质期助手 MVP 产品设计文档 2

> 版本：V0.3 · 状态：首页卡片方案修订稿 · 更新日期：2026-09-07
>
> 本文基于 [MVP 产品设计文档 V0.1](./mvp-product-design.md)，重点说明新增首页和库存页重构；未提及的录入、详情、提醒、历史与设置规则继续沿用原方案。

## 1. 调整目标

当前“首页”同时承载库存概览、搜索筛选和完整列表，用户查看全局状态与查找具体物品时容易互相干扰。

本次将两个任务拆开：

- **首页**：快速回答“当前有多少物品、各状态分别有多少、整体库存是否正常”。
- **库存**：集中查找和管理在库及已用完物品，让搜索与筛选可以直接点击、自由组合。

整体继续保持轻量，不增加复杂图表、报表或智能建议。

## 2. 信息架构

底部 Tab 调整为三项：

| Tab | 核心职责 |
| --- | --- |
| 首页 | 五项核心状态卡片、快捷入口 |
| 库存 | 在库与已用完物品、搜索与组合筛选 |
| 我的 | 默认设置、提醒说明、历史记录 |

小程序默认进入首页。新增/编辑页和物品详情页继续作为二级页面，不进入 Tab。

## 3. 首页

### 3.1 页面重点

首页只保留五个用户最关心的数字，并直接使用卡片展示：

| 卡片 | 统计口径 |
| --- | --- |
| 物品总数 | 当前所有“使用中”的物品品项数 |
| 已过期 | 使用中且到期日早于今天的品项数 |
| 临期 | 使用中且今天至未来 7 天内到期的品项数 |
| 已用完 | 累计标记为“已用完”的品项数 |
| 状态良好 | 使用中且距离到期超过 7 天的品项数 |

五项数据均按物品记录计数，不累加“数量”字段，避免件、瓶、盒等不同单位混算。“物品总数”只表示当前在库品项；“已用完”是独立的累计结果，不包含在物品总数中。

首页不再展示待处理列表、搜索框或完整库存列表，只保留状态卡片和新增入口，让用户一眼掌握全局。

### 3.2 状态与跳转

- 五张卡片整卡可点击，进入库存页并自动选中对应筛选。
- “物品总数”进入全部在库物品；其余卡片分别进入已过期、临期、已用完和状态良好列表。
- 卡片数量为 0 时仍正常展示，点击后显示对应空结果，保持交互一致。
- 页面保留清晰的“新增物品”主操作；没有库存时显示五项零值，并引导新增第一件物品。

### 3.3 页面结构示意

```text
库存概览
┌──────────────────────────┐
│ 物品总数                  │
│ 26             当前在库  │
└──────────────────────────┘

┌────────────┐  ┌────────────┐
│ 已过期   1 │  │ 临期     3 │
└────────────┘  └────────────┘
┌────────────┐  ┌────────────┐
│ 已用完  18 │  │ 状态良好 22│
└────────────┘  └────────────┘

                         ＋ 新增
```

- “物品总数”使用通栏主卡，建立第一视觉焦点；四张状态卡使用统一的 2×2 网格。
- 主卡使用克制的深绿色，状态卡以白色或极浅底色、细边框和充足留白为主。
- 数字是卡片第一层级，名称是第二层级；红色只提示过期，琥珀色只提示临期，良好使用绿色，已用完使用中性色。
- 不使用高饱和渐变、大面积状态色、复杂图表或无意义装饰；统一圆角、间距和按压反馈，保持简洁精致。

## 4. 库存页重构

### 4.1 页面结构

库存页从上到下固定为：

1. 搜索框
2. 种类筛选行
3. 状态筛选行
4. 清除条件入口（有筛选时出现）
5. 库存列表

原首页的全局概览移到新首页，库存页专注查找和管理。

### 4.2 搜索

- 搜索框位于页面最顶部，按物品名称搜索。
- 输入后自动刷新结果，不要求点击确认按钮。
- 有内容时提供一键清空；清空后保留已选的种类和状态。

### 4.3 两行直接筛选

所有选项直接平铺展示，不使用下拉框、弹窗或二次选择。

**第一行 · 种类**

`全部 / 食品 / 药品 / 日化 / 其他`

**第二行 · 物品状态**

`全部在库 / 已过期 / 临期 / 状态良好 / 已用完`

状态口径：

| 选项 | 条件 |
| --- | --- |
| 全部在库 | 所有“使用中”的物品 |
| 已过期 | 使用中且到期日早于今天 |
| 临期 | 使用中且今天至未来 7 天内到期 |
| 状态良好 | 使用中且距离到期超过 7 天 |
| 已用完 | 已标记为“已用完”的物品 |

每一行均为单选，状态默认选中“全部在库”。选中态需要同时使用底色、描边和文字表达，不能只依赖颜色。两行选项在常见手机宽度内都应完整显示，不折叠为下拉选择。

存放位置继续展示在物品信息中，但不再占用主筛选区；后续只有在真实使用反馈表明它是高频条件时再考虑恢复。

### 4.4 组合规则

搜索、种类和状态按“同时满足”组合：

`名称包含搜索词 AND 属于所选种类 AND 符合所选状态`

- 种类与状态切换后立即生效，不需要“确定”。
- 点击种类的“全部”只清除种类条件；点击“全部在库”只恢复默认库存状态，不影响搜索和种类。
- 有任意条件生效时显示“清除全部”，可一次恢复全部在库物品。
- 无匹配结果时保留当前条件，并提供“清除筛选”操作。

### 4.5 列表规则

- 默认展示“使用中”的有效库存；选择“已用完”后展示对应完成记录。已丢弃物品仍在“我的 → 历史记录”中查看。
- 在库结果按到期时间从近到远排列；已用完结果按完成时间从近到远排列。
- 选择“全部在库”时可继续按详细到期状态分组；选中具体状态后直接展示该状态结果，减少重复标题。
- 新增按钮继续固定在易触达位置，并避免遮挡最后一条库存。

## 5. 关键交互闭环

```text
首页查看全局状态
  ├─ 点击任一卡片 → 带筛选进入对应库存列表
  ├─ 点击列表物品 → 查看详情或历史状态
  └─ 点击新增 → 录入物品 → 返回后刷新首页与库存

库存查找物品
  └─ 搜索 + 种类 + 状态 → 组合结果 → 查看或处理物品
```

首页和库存共用同一套实时到期规则。新增、编辑或处理物品后，两个页面再次显示时都应刷新数据，避免概览与列表不一致。

## 6. 数据与实现边界

- 不新增库存业务字段；到期状态继续根据到期日实时计算，不写死在数据中。
- 首页五项统计和库存状态筛选可复用现有库存查询能力，按需补充已用完数量和状态参数。
- 搜索与筛选必须在服务端组合后再分页，不能只过滤当前已加载的一页。
- 首页只展示五张状态卡和新增入口，不为了“看起来丰富”增加列表、趋势图、分类占比或消费建议。

## 7. 验收要点

- 底部清晰展示“首页 / 库存 / 我的”，默认进入首页。
- 首页完整展示物品总数、已过期、临期、已用完和状态良好五张卡片，统计口径正确。
- 五张卡片均可进入库存页，落地后的筛选选中态与结果正确。
- 库存页顶部依次为搜索、种类、状态，所有筛选均可直接点击。
- 搜索、种类、状态任意两项或三项组合时结果正确。
- 物品总数等于已过期、临期与状态良好之和；已用完数量单独统计。
- 空库存、状态数量为 0、无筛选结果和网络失败均有明确反馈。
- 小屏下筛选不重叠、不截断，触控区域足够，状态不只依赖颜色表达。

## 8. 本次不调整

- 新增/编辑、物品详情、提醒、历史记录和默认设置的核心流程。
- 分类、存放位置和库存业务状态的数据定义。
- 家庭共享、图表分析、AI 建议、购物清单等后续能力。
