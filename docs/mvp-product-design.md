# 保质期助手 MVP 产品设计文档

> 版本：V0.1 · 状态：首版方向稿 · 更新日期：2026-09-06

## 1. 产品概述

### 1.1 产品定位

保质期助手是一款面向家庭用户的微信小程序，帮助用户记录食品、药品和日化用品的到期时间，快速发现临期物品，并及时完成使用或清理。

首版专注解决一个问题：**家里的东西什么时候过期，以及现在应该优先处理什么。**

### 1.2 目标用户

- 经常采购、整理冰箱或家庭物资的人
- 容易忘记食品、药品、护肤品到期时间的人
- 希望减少家庭浪费，但不想维护复杂库存表的人

### 1.3 产品原则

- 录入要快，只要求必要信息
- 临期状态要一眼可见
- 处理库存要简单、明确
- 不依赖消息提醒也能正常使用
- 首版优先跑通闭环，不建设完整的家庭资产管理系统

## 2. MVP 目标与边界

### 2.1 核心目标

跑通以下核心闭环：

`录入物品 → 查看临期状态 → 接收提醒 → 标记用完或丢弃`

通过首版验证：

- 用户是否愿意持续录入物品
- 临期信息是否能帮助用户及时处理库存
- 微信提醒是否能提高用户回访和处理效率

### 2.2 首版范围

- 单个微信用户管理自己的家庭库存
- 手工快速录入物品
- 自动计算和展示临期状态
- 库存搜索、筛选与处理
- 小程序内提醒和可选的微信订阅提醒
- 简单历史记录与默认设置

### 2.3 首版不做

- 家庭成员邀请、多人共享和权限管理
- 条码商品库、OCR 和图片识别
- 购物清单、缺货提醒和价格记录
- AI 菜谱、营养分析和消费建议
- 多仓库、批量导入和复杂统计报表
- 会员、积分、社区和商业化功能

## 3. 信息架构

首版控制为四类页面：

1. **首页**：临期概览、库存列表、搜索筛选
2. **新增/编辑页**：录入和修改物品
3. **物品详情页**：查看信息并处理库存
4. **我的**：默认设置、历史记录、产品说明

首页提供固定的新增入口，用户无需进入多级菜单即可开始录入。

## 4. 功能设计

### 4.1 首页

#### 临期概览

展示当前最需要关注的信息：

- 已过期数量
- 7 天内到期数量
- 当前有效库存总数

#### 库存列表

库存按到期时间从近到远排列，并按照以下状态分组：

- 已过期
- 今天到期
- 3 天内到期
- 7 天内到期
- 暂时安全

每条物品展示：

- 名称
- 数量和单位
- 分类或存放位置
- “今天到期”“还有 2 天”“已过期 3 天”等状态文案

#### 搜索与筛选

- 按名称搜索
- 按分类筛选
- 按存放位置筛选
- 支持恢复为全部库存

### 4.2 新增/编辑物品

#### 必填信息

- 物品名称
- 到期信息

到期信息支持两种录入方式：

1. 直接选择到期日期
2. 选择生产日期并填写保质期，由系统计算到期日期

#### 可选信息

- 数量，默认 1
- 单位，默认“件”
- 分类：食品、药品、日化、其他
- 存放位置：冷藏、冷冻、橱柜、药箱、其他
- 提前提醒天数，默认 3 天

保存成功后返回首页，并立即显示最新临期状态。用户拒绝提醒授权时，不影响物品保存。

### 4.3 物品详情

展示物品的完整信息和当前状态，提供以下操作：

- 编辑物品
- 数量减一
- 标记已用完
- 标记已丢弃
- 删除误录记录
- 开启本次临期提醒

当数量减为 0 时，引导用户将物品标记为已用完。删除操作需要二次确认；已用完和已丢弃记录进入历史，不直接删除。

### 4.4 我的

#### 默认设置

- 默认提前提醒天数
- 默认存放位置
- 提醒授权状态说明

#### 历史记录

- 已用完物品
- 已丢弃物品
- 支持按名称搜索

首版只展示记录，不提供复杂数据图表。

## 5. 核心业务规则

### 5.1 临期状态

系统按自然日期计算状态：

| 条件 | 状态 |
| --- | --- |
| 到期日早于今天 | 已过期 |
| 到期日等于今天 | 今天到期 |
| 距离到期 1～3 天 | 3 天内到期 |
| 距离到期 4～7 天 | 7 天内到期 |
| 距离到期超过 7 天 | 暂时安全 |

临期状态由到期日期实时计算，不保存为固定字段，避免日期变化后状态失效。

### 5.2 库存状态

物品只保存以下业务状态：

- 使用中
- 已用完
- 已丢弃

只有“使用中”的物品参与首页统计和临期排序。

### 5.3 提醒规则

- 小程序内持续展示临期状态，不需要用户授权
- 微信订阅消息由用户主动开启
- 每件物品首版只发送一次临期提醒
- 同一物品、同一提醒节点不得重复发送
- 提醒消息点击后进入对应物品详情
- 用户拒绝或关闭提醒时，不影响其他功能

## 6. 核心数据对象

### 6.1 库存物品

主要包含：

- 用户标识
- 物品名称
- 分类和存放位置
- 数量和单位
- 生产日期、保质期、到期日期
- 提前提醒天数和提醒状态
- 库存状态
- 创建、更新和完成时间

### 6.2 用户设置

主要包含默认提醒天数、默认存放位置等个人偏好。

### 6.3 提醒记录

记录物品、计划提醒日期、发送结果和发送时间，用于避免重复提醒和排查失败原因。

## 7. 体验要求

- 新用户不需要填写资料或手工注册
- 首页打开后优先展示最紧急物品
- 新增一件物品尽量控制在 20 秒左右
- 状态不能只依赖颜色，还需要明确文字
- 空库存、无搜索结果、网络失败都要有清晰提示
- 关键操作给出及时反馈，危险操作需要确认
- 整体视觉保持清爽、可信，避免过多卡片和装饰

## 8. MVP 验收标准

- 可以完成物品的新增、查看、编辑和删除
- 可以通过两种日期方式得到正确的到期日
- 首页临期分组、数量统计和排序正确
- 可以搜索并按分类、位置筛选库存
- 可以减少数量、标记已用完或已丢弃
- 已处理物品不再出现在有效库存中，并可在历史记录查看
- 用户拒绝提醒授权后仍可正常使用
- 同一提醒不会被重复发送
- 关闭并重新进入小程序后数据仍然存在
- 不同用户之间的数据相互隔离
- 在微信真机完成一次完整核心流程

## 9. 效果衡量

首版重点观察以下指标：

- 首次进入后成功新增物品的用户比例
- 每位用户录入的有效物品数量
- 7 日内再次打开小程序的用户比例
- 临期物品被标记用完或丢弃的比例
- 提醒授权率和提醒消息打开率

这些指标用于判断核心闭环是否成立，不在首版建设复杂分析后台。

## 10. 后续方向

核心闭环验证有效后，再按优先级考虑：

1. 家庭成员共享库存
2. 最近录入和常用物品模板
3. 开封后保质期管理
4. 图片、条码和日期识别
5. 购物清单与库存不足提醒
6. 浪费统计和智能建议
