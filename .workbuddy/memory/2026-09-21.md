# 2026-09-21

## 到期提醒（服务通知）不送达 — 定位并修掉根因

- **根因**：`wx.requestSubscribeMessage` 必须由用户 tap 事件同步触发。原实现两处
  （`item-form-sheet.save()`、`quick-entry.persistDrafts()`）都在 `await saveItem()` 之后才
  申请授权 → 每次都被 `fail can only be invoked by user TAP gesture` 拒掉 → 微信侧订阅额度
  恒为 0 → 云端 `subscribeMessage.send` 必然失败 → 服务通知永远不来。
- **修法**：把授权请求提到第一个 `await` 之前（async 函数在首个 await 前的代码仍在 tap
  同步栈里），只把 Promise 留给保存成功后收结果。新增 `requiresReminderSetup()` /
  `hasReminderTarget()` 用同步数据判定「要不要申请」，判据与各自 arm 侧严格对齐。
  提交 `990467d`（分支 `index-ui`）。push 时 VPN 未开、7888 未监听 → **只提交未推送**。
- **微信硬限制**：一次性订阅 = 一次点击换一条额度。批量快速录入 N 条只有 1 条能真正收到，
  其余 `43101`。两条路待龙哥定：维持现状，或加「逐条开启提醒」列表（唯一能绕开限制的做法）。
- **云函数 CLI 跑不了**：`D:\微信web开发者工具\cli.bat` 内部调 `reg.exe`，本机沙箱把 reg.exe
  拉进了程序黑名单，`cloud functions list/download/deploy` 全部被拦且提示不可绕过 →
  云端状态这轮只能用控制台人工确认。
- 新增 `docs/reminder-notification-troubleshooting.md`：云端 4 项待核对清单（MINIPROGRAM_STATE
  与运行版本是否一致、定时触发器、`subscribeMessage.send` 权限、模板字段）、手工造数据触发
  派发的「马上测一条」步骤、`failureCode` 对照表（43101/47003/40037/41030）。
