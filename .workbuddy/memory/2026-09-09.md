## UI 三处修复

- **自定义 tab 栏加号被裁**：原实现把圆形放在 `button.tabbar__add`（高 104rpx）里用 `margin-top: -30rpx` 顶上去，
  微信 `wx-button` 基础样式带 `overflow: hidden`（且 tabBar 容器也可能裁剪），凸起部分被切掉。
  改法：加号按钮从 bar 里拿出来，`position: fixed` + `left/right: 0` + `margin: 0 auto` 居中，
  `overflow: visible; z-index: 1000`；圆形 100rpx，`bottom: calc(54rpx + env(safe-area-inset-bottom))`，
  圆心正好落在 bar 顶边（104rpx）→ 上半圆完整凸出。bar 内用 `.tabbar__add-slot`（flex 0 0 150rpx）占位。
  **结论：自定义 tabBar 的凸起元素不要靠负 margin 溢出父级，单独 fixed 定位最稳。**
- **批量操作页标题**：导航栏标题固定 `批量操作`；页内标题按实际筛选状态算
  （`VIEW_STATUS_TITLE`: active_all 全部在库 / expiring 临期 / expired 已过期 / safe 状态良好 / used_up 已用完 / trash 回收站）。
  之前只按 `source` 取值，从首页进来恒为「临期物品批量操作」。
- **快速录入拍日期提示**：OCR 未接入时保留按钮，提示由「暂时未接入，敬请期待」改为
  「拍照识别未开通，请手动选日期」；语音仍用原文案。常量 `DATE_PHOTO_PENDING_TOAST`。

校验：`npm run check` 全绿（11 文件 83 测试 + 项目结构检查）。

## 首页物品卡片数量步进器重做（第四轮）

用户反馈：加减号背景圆过大、加号消失、热区不对、不对齐。

- **根因**：`.item-card__step` 是 88rpx 的 `button`，圆底与 +/− 符号全靠 `::before`/`::after` 伪元素渲染（button 上伪元素不可靠）；
  且 88×2 + gap 已超过 `.item-card__side` 的 172rpx，步进器溢出被挤，右侧加号显示异常。
- **改法**：符号改为真实节点——`button.item-card__step`（纯热区，70rpx×92rpx）内嵌
  `view.item-card__disc`（48rpx 圆底）+ `view.item-card__disc-bar`（横 20×4rpx，`--vertical` 竖 4×20rpx），
  disc 用 flex 居中 + bar 绝对定位 `translate(-50%,-50%)`，符号与圆心严格重合。
  数量区拆成 `text.item-card__quantity-value` + `text.item-card__quantity-unit`（原来数字和单位挤在一个 text 里）。
- **布局**：`.item-card__side` 172rpx→196rpx（小屏 176rpx），步进器 `height: 92rpx` + `space-between` + `align-items: center`；
  remaining 与步进器 gap 24→20rpx。数量区 `flex:1; min-width:0; overflow:hidden`，3 位数字不溢出。
- **经验**：小程序交互元素里的图形不要用 button 伪元素画，button 只当热区容器，图形用内部 `view` 画。
- 校验：`typecheck` / `check:project` 通过；`vitest` 12 文件 4 个失败（全在 `quick-entry-page.test.ts`，
  `photoStage`/`voiceState` 未接入时应为 `idle` 却变成 `camera`/录音态），**与本次改动无关，属既有失败待修**。

## 本地 .git 损坏与恢复（重要事故记录）

- **现象**：git 突然报 `fatal: not a git repository`，但 `.git` 目录存在。
  排查发现 `.git/refs/` 整个目录消失，且 `.git/objects/pack/` 只剩 `.idx` 文件、`.pack` 文件全没了 → 本地历史对象不可恢复。
- **恢复步骤**：① 先备份工作区源码到 `D:\myProject\_freshKeeper_backup_20260909`（含旧 `.git` → `dotgit-broken`）；
  ② HTTPS clone 远端到临时目录；③ 把新 `.git` 替换进工作区（Git Bash 的 `mv` 对 `.git` 报 Permission denied，
  改用 PowerShell `Move-Item -Force` 成功）；④ `git branch index-ui origin/index-ui` + `git symbolic-ref HEAD refs/heads/index-ui`
  + `git reset --mixed` —— **只动 HEAD/index，不 checkout，工作区文件原样保留**；⑤ status 显示的差异就是未推送的内容，重新 commit。
  结果内容零丢失（工作区本来就是最新状态）。
- **push 结论**：HTTPS 地址没有保存凭据会卡住/报 `could not read Username`；**用 SSH（`git@github.com:...`）push 实际是成功的**
  （`417b21e..a52c034 index-ui -> index-ui`），之前"SSH 22 被拦"的结论不成立，优先试 SSH。
- 备份目录 `D:\myProject\_freshKeeper_backup_20260909` 还在，确认无误后可自行删除。
