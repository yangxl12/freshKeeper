## 部署 inventoryApi：踩了「漏 `--remote-npm-install`」的坑，线上先崩后修

龙哥说「部署」，于是跑第一条：

```
cli.bat cloud functions deploy --env cloud1-d0gkh66ce94b1be08 --names inventoryApi --project ...
```

结果 `success: true / filesCount 2982 / packSize 3.2 MB` —— **这体量就是错的**（正常应十几个文件）。
部署完跑探针，首页 `listErrorMessage = "列表未更新：服务暂时不可用，请稍后重试"`，
重试两次都失败 → 不是冷启动，是**线上函数彻底不可用**（不只首页卡片，整个 inventoryApi 都挂了）。

**根因**：本地 `cloudfunctions/inventoryApi/node_modules` 是**残缺**的，缺 `wx-server-sdk` 依赖的
`@cloudbase/node-sdk`。不带 `-r` 时这包整个被打包上传 → 云端 `require('wx-server-sdk')` 立刻抛
`Cannot find module '@cloudbase/node-sdk'` → 每次调用都崩，客户端只能给统一的「服务暂时不可用」，
从报错完全看不出根因。

本地一秒复现（以后排查部署问题先跑这个）：

```
node -e "try{require('./cloudfunctions/inventoryApi/index.js');console.log('LOAD_OK')}catch(e){console.log('LOAD_FAIL '+e.stack)}"
```

**修法**：加 `--remote-npm-install` 重部署。第一次被拒
（`FailedOperation.UpdateFunctionCode: 当前函数处于Updating状态`），等 75s 后重跑成功：
`filesCount 12 / 34.2 KB`。再跑探针 → overview 到位、`listErrorMessage` 空、骨架卡 0、缓存 dateKey 是今天。

**教训（已写进 MEMORY.md 与 `docs/cloud-deployment.md` §部署）**：
1. `--remote-npm-install` 是**必填**，不是可选。
2. 部署完先看 `filesCount`：上千 = 打包错了。
3. 部署后必须端到端验一次，别只看 `success: true` —— CLI 只看上传成功，不看函数能不能跑。
4. `engines.node: 20` / `wx-server-sdk@4.0.2` 是唯一依赖，云端安装没问题。

## 修复：首页卡片封面不显示（fileID 拼参缩略图已回滚，466294a）

**现象**：龙哥反馈「添加物品后首页卡片里的图片没了，AI 生图是不是没了」。

**排查**（探针逐段实测，不靠读代码推理）——**AI 生图和数据层都是好的**：
- 首页 6/6 物品都有 `coverFileId`，说明云端生图 + 落库正常，功能没丢
- `getImageInfo(原 fileID)` → `ok`，1024×1024 jpeg
- `getImageInfo(fileID + '?imageView2/2/w/200/h/200/format/webp/q/80')` → **`file not found`**
- `imageMogr2` 写法同样 `file not found`

**根因**：`cloud://` 是**文件标识不是 URL**，后面拼接任何查询参数都会被当成文件路径的一部分 →
卡片 `<image>` 加载失败 → `binderror` → `handleCoverError()` → 回退默认占位图。
这是 `6e09437`「性能分析第一批优化」引入的回归：当时把「云存储支持在 fileID 后拼接图片处理参数」
这个**从未验证过的前提**直接当结论写进了方案。官方口径：**必须改用 url 才支持图片处理，fileID 不支持**。

**修法**：`domain/inventory.ts:coverThumbUrl` 直接返回原 fileID（`COVER_THUMB_QUERY = ''`），
列表回到原图直出，功能恢复。同步修正 `docs/performance-analysis.md` 的 §3.6 与第 1 批表格。

**将来要做缩略图的完整前提（别只改那个常量）**：① 云存储开通「图像处理」扩展 + 所有人可读权限；
② 用 `wx.cloud.getTempFileURL` 把 fileID 转 https URL 再拼参数（临时 URL 有时效，需缓存/刷新策略）；
③ 保留原 `coverFileId` 给详情页。目前唯一零依赖的省流量手段是**降 `IMAGE_SIZE` 到 512²**。

**验证**：重建后探针确认卡片 `coverThumb` 已是干净 fileID，前 4 条封面 **4/4 可加载（修复前 0/4）**；
`npm run check` 全绿（33 文件 / 448 用例）。

**新踩到的工具坑**：`Page.getElements` / `Page.getElement` 这轮报
`appservice Page.getElements unimplemented`（上一轮还能返回 `{elements:[]}`）——「数节点」这条验证路
不可靠，而且自定义组件内部节点本来就查不到（页面层选择器不穿透 `>>>` 也不行）。
**验图片这类问题改用 `App.callWxMethod` + `getImageInfo` 直接打 URL，才是硬证据。**
