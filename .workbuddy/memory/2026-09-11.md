### 关键平台约束（别再踩）
- **微信订阅消息授权是系统级状态，小程序既写不进也关不掉**。唯一数据源是
  `wx.getSetting({ withSubscriptions: true })` → `subscriptionsSetting.mainSwitch`
  （`undefined` = 用户从未授权过，微信不下发状态，当未开启处理）。
  改授权只能 `wx.openSetting({ withSubscriptions: true })` 让用户自己点。
- 因此「提醒授权」开关**故意不落任何本地状态**：`bindchange` 里不读 `event.detail.value`，
  只弹弹窗 + 引导去系统页。若真写成受控开关，用户拨到关会立刻回弹 → 假开关。
- **开关回弹技巧**：拨动后 switch 内部状态已变，setData 同值不一定刷回。用
  `authSwitchRebuilding` + `wx:if` 把 switch 卸载重建（在弹窗遮罩盖住表单后做，用户无感）。
- 同步靠"每次重新读"而不是"存下来"：组件 `lifetimes.attached` + `pageLifetimes.show`
  各读一次，`closeReminderSettings` 和 `openSetting` 的 complete 再兜底读。
  `pageLifetimes` 在本项目首次使用，`this` 类型正常（strict 模式下 tsc 通过）。

## 修 bug：提醒授权关了仍显示「通知已开启」（commit a17957e，已推 index-ui）

龙哥反馈：在微信设置里关掉授权后，弹窗里「提醒授权」还是「通知已开启」。

**根因（探针实测确认，不是缓存）**：`wx.getSetting({withSubscriptions:true})` 真实返回是
`{ mainSwitch: true, itemSettings: { <模板ID>: 'reject' } }` —— 用户关掉的是**「临期提醒」这个模板**的授权，
`mainSwitch`（订阅消息总开关）根本没变。第一版实现只读 `mainSwitch`，判据用错了。

- 修法：`services/reminder-service.ts` 新增纯函数 `resolveReminderAuthorization` +
  异步 `readReminderAuthorization`，折算四态 `authorized / main-switch-off / template-rejected / unrequested`；
  「完整录入」和「我的—提醒设置」两处消费端改为共用它，删掉 mine 页原来的 `updateSubscriptionSummary`。
- 补 `tests/unit/reminder-authorization.test.ts` 7 个用例（reject / ban / 无记录 / 总开关关 / 未下发）。
- `npm run check` 全绿：211 tests / 16 files。

## 快录页四项调整：上限 20 / 倒序 / 卡片进编辑复用完整录入表单 / 光标对齐

文件：`pages/quick-entry/{ts,wxml,wxss}`、`components/item-form-sheet/{ts,wxml}`、
`domain/quick-entry.ts`、两个测试文件、`docs/quick-entry-acceptance.md`。

- **1 条上限 20**：`MAX_DRAFTS` 5→20（只改客户端累积上限；云端「一次解析最多 5 条」不动，
  那是 `date-facts.js` / `quick-text.js` 的单请求上限）。新增派生数据 `draftLimitReached`
  （`countUnfinished(drafts) >= MAX_DRAFTS`，已入库卡片不占名额），
  「从最近录入添加」`disabled="{{saving || recognitionState !== 'idle' || draftLimitReached}}"`，
  并在输入卡片下方给一行 `feature-hint` 说明（沿用「置灰必须给说明」的约定）。
- **2 编辑页复用完整录入表单**：给 `item-form-sheet` 加 `purpose` 属性（`'save'` 默认 / `'draft'`）。
  draft 模式下 `save()` 不写库，改为 `triggerEvent('draftsubmit', collectDraftFields())`；
  快录页把旧的 `.draft-editor` 内嵌表单整块删掉，换成整屏 overlay + `<item-form-sheet id="draftForm" purpose="draft">`，
  底部沿用组件自带的 fixed `.save-bar` 当「完成」按钮（所以别给 overlay 加底部按钮）。
  **组件新加 `dirty` 跟踪 + `isDirty()`**：快录页退出时问一次（改过才问），没改动直接退。
  domain 新增 `draftToFormPrefill()`（如实回填，含冲突日期；别用 `draftToManualFields`，
  它会把有问题的字段裁掉）和 `applyFormValuesToDraft()`（**日期没动过就保留 dateConflict**，
  否则「没改就点完成」会静默吃掉日期冲突）。
  同时删掉了旧的 `handleTextInput/handleDateChange/handleModeChange/chooseCandidate/confirmFallback`
  和整块 `.qe-*` / `.candidate-*` / 页级 `.mode-switch` 样式——编辑表单只有一份了。
  **代价**：草稿编辑里不再有日期候选列表，且「到期计算」切模式会像完整录入一样清空另一种模式的值。
- **3 后添加的在前 + 末条被遮挡**：`generateDrafts` 改成 `[...built.drafts, ...existing]`（新一批整批插顶、批内保持原文顺序），
  `selectRecent` / `recognizePhoto` 也改成前插；`editingIndex` 随之从 `drafts.length` 变 `0`。
  遮挡是因为 `.quick-footer` 是 fixed，`.quick-body` 只留了 24rpx —— 加 `.quick-body--with-footer`（204rpx + 安全区）。
- **4 输入框光标与 placeholder 错位**：根因是 `.quick-input` 上 `line-height: 76rpx`：
  Android 微信原生 textarea 的**文字/光标按 line-height 居中、placeholder 行内居顶**，差距随 line-height 线性放大。
  修法：行高改回 36rpx（贴合 28rpx 字号）、76rpx 高度由 `padding: 20rpx 6rpx` 撑出，
  placeholder 单独给 `placeholder-class="quick-input-placeholder"`（同 font-size/line-height），
  textarea 补 `disable-default-padding="{{true}}"` 去掉 iOS 默认内边距。
  **这条是平台行为，别再给 textarea 设大 line-height。**
